# 味热比

**味热比 = 爱吃程度 ÷ 每百大卡热量**

一样东西有多值得这口热量：同样 300 大卡，一份你很爱吃的和一份你一般般的，减脂时该留哪个，答案不言自明。

## 爱吃程度从哪来

按优先级：

1. **用户自己设的**（`love set`）：0～10 分，0 表示不吃，永远不推荐。
2. **大众口味 + 常点加成**：默认值来自麦购网「麦当劳十大最受欢迎产品」综合指数，换算成 10 分制。这个指数汇总了大众点评、美团、饿了么上的评价与热销情况，算法没有公开，所以只作为起点。用户有历史订单时，`learn` 会给常点的餐品每单加 0.3，最多加 2。
3. **默认值 6.0**：榜单上没有的餐品先给中间值，回复时要说明"暂无大众口味数据"。

| 大众口味 | 爱吃程度 | 匹配的餐品 |
|---|---|---|
| 薯条 | 9.2 | 名字含"薯条" |
| 麦辣鸡翅 | 9.1 | 麦辣鸡翅开头 |
| 巨无霸 | 8.9 | 巨无霸 |
| 麦旋风 | 8.7 | 名字含"麦旋风" |
| 麦乐鸡 | 8.4 | 麦乐鸡开头 |
| 圆筒冰淇淋 | 8.3 | 圆筒冰淇淋 |
| 麦辣鸡腿汉堡 | 8.1 | 麦辣鸡腿汉堡 |
| 麦麦脆汁鸡 | 8.0 | 麦麦脆汁鸡开头 |

按这套大众默认值算，**圆筒冰淇淋是最值这口热量的（8.9），麦辣鸡腿汉堡和巨无霸最不值（约 1.7）**。这是一个可以拿来聊的有趣结论，但要说清楚它来自大众口味，用户自己的口味可以改。

0 大卡的饮料（无糖可乐、美式等）不占热量，不参与味热比排序。

## 换东西的代价

热量超了要换掉一样东西时，比的不是单样的味热比，而是**换掉它的代价**：

> 代价 = 少掉的爱吃程度 ÷ 少掉的热量（每百大卡）

例子（大众默认值）：

| 换法 | 少吃 | 爱吃程度变化 | 代价 |
|---|---|---|---|
| 可乐 → 无糖可乐 | 147 大卡 | 6.0 → 6.0 | 0 |
| 巨无霸 → 麦乐鸡 5 块 | 300 大卡 | 8.9 → 8.4 | 0.17 |
| 中薯条 → 小杯玉米杯 | 236 大卡 | 9.2 → 6.0 | 1.36 |

代价越小越先换。所以可乐最先换，薯条最后才动，哪怕薯条单看味热比并不低：因为它是"大众最爱"，换掉它最心疼。

## 脚本怎么排一顿

1. 老样子放得下这顿的预算，就原样保留，另给两个同样放得下的选项。
2. 放不下，就在所有候选套餐的所有换配组合里打分，挑最高的：
   - 爱吃程度总和（主要部分）
   - 补蛋白质：每 10g 加 1 分，最多补到当天的缺口（维持模式减半）
   - 每改动老样子一处扣 0.3 分（尽量别改太多）
   - 每 1 大卡扣 0.002 分、每 1 元扣 0.08 分（同样喜欢时，热量低、便宜的优先）
3. 把方案和老样子的每处差别列出来，按代价从小到大排，就是给用户看的"我这样换"。
4. 套餐怎么都放不下：给出能放下的单点（按爱吃程度排），以及最轻的套餐会超多少。明确说不建议靠饿一顿抵消。

所有热量来自 `list-nutrition-foods`，价格估算来自 `query-meals` 现价加 `query-meal-detail` 差价，最终以 `calculate-price` 为准（实测四种配法，估算与官方核价完全一致）。
